## 1. Запуск и сборка проекта

### Требования
- Node.js версии 20+ (протестировано на Node.js v24)
- npm версии 10+

### Установка зависимостей
```bash
npm install
```

### Запуск сервера разработки (с поддержкой mock API)
```bash
npm run dev
```
Приложение откроется по адресу `http://localhost:5173`.  
Все запросы к `/api/samples` обрабатываются встроенным middleware Vite и отображаются во вкладке **Network (Сеть)** инструментов разработчика браузера (код ответа `200 OK`).

### Сборка для публикации (Production Build)
```bash
npm run build
```
Статические файлы будут сгенерированы в папку `dist/`.

## 2. Архитектура приложения и ограничения
- **Никакого Redux и Context API:** В соответствии с требованиями лабораторной работы управление состоянием реализовано исключительно на стандартных React-хуках (`useState`, `useEffect`, `useCallback`, `useMemo`) с передачей данных вниз по дереву компонентов через `props`.
- **Mock-сервис:** Получение данных производится через клиентский сервис `sampleService.ts` с HTTP-запросами к `/api/samples`, что обеспечивает наглядность во вкладке **Network** инструментов разработчика без необходимости запуска внешнего бэкенда.
- **Медиаресурсы по умолчанию:** При отсутствии или ошибке загрузки фото/видео карточка использует локальные ассеты `default-image.svg` и `default-video.mp4`.

## 3. Описание страниц приложения, кнопок и полей ввода

### 3.1. Страница «Плитка» (`TileView`) — Каталог химических образцов
Предназначена для гостевого просмотра каталога опубликованных образцов с возможностью фильтрации и сортировки.
- **Информационный бейдж:** «Показано: N» — текущее количество отображаемых карточек.
- **Компонент фильтрации (`FilterBar`):**
  - **Поле ввода «Поиск по названию образца»** (`Form.Control`): строковый фильтр для быстрого поиска по наименованию или описанию минерала.
  - **Ползунок «Объем газа (мл из 1 кг)»** (`Form.Range`): числовой диапазон от 0 до 100 мл с динамическим индикатором текущего значения.
  - **Выпадающий список «Сортировать по»** (`Form.Select`): выбор критерия упорядочивания (По умолчанию, По названию А-Я, По объему газа, По доле примесей, По лайкам).
  - **Кнопка «Найти»** (`Button variant="primary"`): отправляет HTTP-запрос `GET /api/samples?gas_volume=X` к mock API, инициируя видимый сетевой запрос в Network.
  - **Кнопка сброса** (`Button variant="outline-secondary"`): сбрасывает все фильтры к исходным значениям и перезагружает полный список образцов.
- **Сетка карточек (`SampleCard`):**
  - Превью изображения (при отсутствии отображается бейдж «Изображение по умолчанию»).
  - Бейдж статуса «Черновик» (для неопубликованных записей).
  - Счетчик лайков (`❤️ N`).
  - Наименование образца.
  - Характеристики химической реакции: объем выделившегося газа (мл) и массовая доля примесей (%).
  - Клик по карточке открывает третью страницу — «Паспорт образца».

### 3.2. Страница «Лента» (`FeedView`) — Вертикальный медиа-просмотр
Полноэкранный вертикальный интерфейс для последовательного просмотра образцов и видеозаписей реакций.
- **Видеоплеер:** воспроизводит видео протекания реакции с постером; при пустом URL подставляет `default-video.mp4` и выводит бейдж «Использовано видео по умолчанию».
- **Информационный оверлей:** наименование образца, расширенное описание, системный ID и статус.
- **Индикаторы параметров реакции:**
  - Капля: массовая доля примесей (%).
  - Облако: объем выделившегося газа (мл).
  - Сердечко: количество отметок «Нравится».
- **Кнопка «Следующий образец»** (круглая кнопка с иконкой `ChevronDown`): выполняет сетевой запрос `GET /api/samples/feed?id=X&next=true` и закольцовано переключает на следующий образец.

### 3.3. Страница «Паспорт образца» (`SampleDetailView`)
Третья страница приложения — подробная аналитическая карточка конкретного образца.
- **Кнопка «Назад к плитке»**: возврат в общий каталог.
- **Кнопка «Смотреть реакцию в ленте»**: моментальный переход в «Ленту» к данному образцу.
- **Сводная таблица параметров:** массовая доля примесей, объем газа на 1 кг, отметки «нравится», даты создания и публикации.

### 3.4. Нижняя навигационная панель (`BottomNav`)
Фиксированный navbar внизу экрана, состоящий из 4 пунктов:
1. **«Лента»** — доступна гостю (переключает на `FeedView`).
2. **«Добавление»** — **недоступна** для роли «Гость» (атрибут `disabled`, затемненный стиль, всплывающая подсказка Tooltip о требовании роли «Создатель»).
3. **«Плитка»** — доступна гостю (переключает на `TileView`).
4. **«Вход»** — **недоступна** для роли «Гость» (атрибут `disabled`, затемненный стиль, всплывающая подсказка Tooltip).
Ровно два пункта являются активными и доступными для гостя.

## 4. Реализация компонентов, передаваемые Props и медиа по умолчанию

### 4.1. Реализация изображения и видео по умолчанию
В проекте предусмотрены файлы:
- `public/media/default-image.svg`
- `public/media/default-video.mp4`

В коде компонента `SampleCard.tsx`:
```tsx
const imageSrc = sample.image_url && sample.image_url.trim() !== ''
  ? sample.image_url
  : DEFAULT_IMAGE;

<Card.Img
  src={imageSrc}
  onError={(e) => { e.currentTarget.src = DEFAULT_IMAGE; }}
/>
```
Если поле `image_url` пустое (как у образцов «Доломит» и «Новый образец»), мгновенно применяется `DEFAULT_IMAGE`. Также обработчик `onError` страхует от битых внешних ссылок.
Аналогично в `FeedView.tsx` для видеопотока:
```tsx
const videoSrc = sample.video_url && sample.video_url.trim() !== ''
  ? sample.video_url
  : DEFAULT_VIDEO;
```

### 4.2. Передаваемые Props между компонентами
1. **`BottomNavProps`:**
   - `activeTab: 'feed' | 'tile'` — текущая активная вкладка;
   - `onSelectTab: (tab: 'feed' | 'tile') => void` — колбэк переключения экрана.
2. **`FilterBarProps`:**
   - `filters: SampleFilterOptions` — объект текущих критериев фильтрации;
   - `onChangeFilter: <K>(key: K, value: ...)` — функция обновления конкретного поля фильтра;
   - `onReset: () => void` — сброс фильтров;
   - `onApplyServerFilter: () => void` — запуск сетевого запроса к mock API;
   - `isLoading: boolean` — флаг сетевой активности.
3. **`SampleCardProps`:**
   - `sample: Sample` — объект образца (id, title, gas_volume, impurities_percent, likes, image_url...);
   - `onSelectSample: (sample: Sample) => void` — колбэк клика по карточке.
4. **`FeedViewProps`:**
   - `sample: Sample | null` — текущий образец для показа;
   - `onNextSample: () => void` — переход к следующему образцу (закольцованная лента);
   - `isLoading: boolean` — индикатор загрузки.

## 5. Все используемые React-хуки

В проекте используются исключительно стандартные хуки React:
1. **`useState`:**
   - `currentView`: переключение между страницами `'tile'`, `'feed'` и `'details'`;
   - `samples`: массив загруженных образцов;
   - `feedSample`: активный образец для ленты;
   - `selectedSample`: образец для страницы детального паспорта;
   - `filters`: состояние формы фильтрации;
   - `isLoading`: индикатор ожидания сетевого ответа.
2. **`useEffect`:**
   - **Эффект 1 (первичная загрузка каталога):** срабатывает один раз при монтировании компонента `App` (`[]`) и запрашивает коллекцию карточек с `/api/samples`.
   - **Эффект 2 (первичная загрузка ленты):** срабатывает при монтировании и запрашивает первый образец для экрана ленты с `/api/samples/feed`.
3. **`useCallback`:**
   - Мемоизирует функции `loadCatalog`, `loadFeed`, `handleApplyServerFilter`, `handleResetFilter`, предотвращая лишние ререндеры дочерних компонентов при изменении других состояний.
4. **`useMemo`:**
   - Мемоизирует вычисление отфильтрованного и отсортированного списка `processedSamples`. Пересчитывается только при изменении `samples`, `searchQuery` или `sortBy`.

## 7. Ответы на контрольные вопросы

### 1. Что такое React?
**React** — это декларативная JavaScript/TypeScript-библиотека с открытым исходным кодом для создания пользовательских интерфейсов (SPA). React основан на компонентном подходе, при котором UI разбивается на изолированные переиспользуемые блоки (компоненты). React использует Virtual DOM (виртуальное дерево объектов) для оптимизации обновлений реального DOM браузера посредством алгоритма согласования (reconciliation / React Fiber).

### 2. Props и состояние (State) — отличия
- **`props` (свойства)** — неизменяемые (read-only) входные параметры, передаваемые от родительского компонента дочернему сверху вниз (однонаправленный поток данных). Дочерний компонент не имеет права мутировать свои props.
- **`state` (состояние)** — внутреннее изменяемое хранилище данных компонента, определяющее его текущий вид и поведение. При изменении состояния через специальную функцию (`setSomething`) React инициирует повторный рендеринг компонента и его дочерних элементов.

### 3. Компонент и элемент — в чем разница?
- **Элемент React (React Element)** — легковесный, неизменяемый объект JavaScript, описывающий, что именно должно появиться на экране (виртуальный узел DOM: `{ type: 'div', props: { children: 'Hello' } }`). Создается вызовом `React.createElement` или синтаксисом JSX.
- **Компонент React (React Component)** — функция (или класс), которая принимает `props` на вход и возвращает React-элемент или их дерево. Компонент инкапсулирует логику, состояние и жизненный цикл.

### 4. Хуки useState и useEffect
- **`useState`** — хук для объявления переменной состояния в функциональном компоненте. Возвращает кортеж из двух значений: текущее состояние и функцию для его обновления: `const [state, setState] = useState(initialValue);`.
- **`useEffect`** — хук для выполнения побочных эффектов (Side Effects): сетевых запросов, подписок на события, манипуляций с таймерами. Принимает функцию эффекта и массив зависимостей `[deps]`. При пустом массиве `[]` эффект запускается один раз при монтировании (аналог `componentDidMount`).

### 5. Жизненный цикл компонента
Жизненный цикл функционального компонента охватывает три основные фазы:
1. **Монтирование (Mounting):** инициализация `useState`, первый рендер и выполнение `useEffect` с пустым массивом зависимостей `[]`.
2. **Обновление (Updating):** изменение `props` или `state`, повторный вызов функции компонента (re-render) и срабатывание `useEffect` с указанными зависимостями `[a, b]`.
3. **Размонтирование (Unmounting):** удаление компонента из DOM, выполнение функции очистки (cleanup function), возвращаемой из `useEffect`.

### 6. Сравнение Vite и Babel
- **Babel** — классический транспайлер JavaScript. Преобразует современный синтаксис ECMAScript (ES6+) и JSX в обратно совместимый JavaScript (ES5) для старых браузеров. Работает на уровне синтаксического AST-дерева файлов.
- **Vite** — современный инструмент сборки нового поколения. В режиме разработки (Dev) Vite использует нативные ES-модули браузера (No-bundle Dev Server) и сверхбыстрый препроцессор `esbuild` (написанный на Go), что дает мгновенный старт сервера и Hot Module Replacement (HMR). Для production-сборки Vite использует оптимизированный бандлер Rollup.
